# 非機能要件・品質基準 (Non-Functional Requirements)

本ドキュメントは、「TurfTalk」における性能・オフライン動作・モバイル対応・アクセシビリティ・セキュリティ・運用コストに関する非機能要件および品質基準を定めます。

---

## 1. 性能要件 (Performance)

スキマ時間（1〜2分）のマイクロラーニング体験を損なわないよう、モバイル端末における初期表示速度およびタップ応答性を最優先とします。

### 1.1 Core Web Vitals 目標目安
| 指標 | 目標目安 | 主な担保策 |
| :--- | :--- | :--- |
| **FCP / LCP**（初回描画・最大コンテンツ描画） | 高速描画（ネットワーク待ちゼロ） | 静的フレーズマスター（`INITIAL_PHRASES`）のバンドル内包による即時描画、Firestore データのバックグラウンド非同期同期、Service Worker による静的アセットキャッシュ |
| **INP**（操作応答性） | タップ直後の即時フィードバック | クイズ解答判定・SE（Web Audio API）のローカル即時実行、不要な再レンダリング抑制 |
| **CLS**（レイアウトシフト） | 視覚的ズレの極小化 | 画像・アニメーション領域のアスペクト比／サイズ確保、ヘッダーおよびプログレスバーの `sticky` 固定 |

### 1.2 バンドルサイズ・アセット最適化
- 不要な外部依存関係や重量級ライブラリを追加せず、軽量な SPA（Vite + React + Tailwind CSS）構成を維持する。
- 競走馬イラスト・背景アセット（JPEG）は Canvas による透過合成とクライアントサイドキャッシュを活用し、描画負荷を抑える。
- 性能改善は推測ではなく計測結果（Lighthouse / Web Vitals 等）に基づいて実施する（詳細は `.agents/rules/30-performance.md` を参照）。

## 2. オフライン動作 & PWA 要件 (Offline & PWA)

混雑した競馬場や地下鉄などの不安定な通信環境・オフライン環境でも、学習コア体験が途切れないことを必須要件とします。

- **オフラインファースト設計**:
  - `vite-plugin-pwa`（Workbox Service Worker）により、HTML/JS/CSS・競走馬立ち絵・疾走スプライト・背景画像・Web Fonts をキャッシュする。
  - フレーズデータは「第1層: 内包静的マスター → 第2層: LocalStorage キャッシュ → 第3層: Firestore 動的同期」の多層構成とし、オフラインでも全問題を出題可能とする。
- **オフライン時の学習進捗保持**:
  - 進捗は常に LocalStorage へ即時保存し、オンライン復帰時およびフォアグラウンド復帰時に Cloud Firestore と非同期同期する。
  - Firebase 未設定・オフライン環境でも認証・同期・Analytics が例外でクラッシュしないフェイルセーフ設計とする。
- **ホーム画面追加（Installability）**:
  - Web App Manifest、Apple Touch Icon（180×180）、フルブリード maskable 対応 PWA アイコン（192×192 / 512×512）を整備し、Android 向けインストールバナーおよび iOS Safari 向け追加手順案内を提供する。

## 3. レスポンシブ & モバイル操作性要件 (Responsive & Mobile UX)

- **モバイルファースト設計**:
  - スマートフォン縦持ち（片手・親指操作）に最適化した `max-w-md` 基準の中央コンテナレイアウトを採用する。
  - 375px〜412px 程度の狭い画面幅でも、ヘッダーのバッジ・ボタンや長い英文フレーズで意図しない横スクロールやテキスト折れが発生しないこと。
- **タップ領域とフィードバック**:
  - クイズ選択肢ボタンは押し間違えを防ぐ十分なタップ領域（縦幅 58px 以上目安）を確保する。
  - 画面遷移およびクイズ・レース問題切り替え時にスクロール位置を最上部へリセットし、次の設問を即座に視認できるようにする。
  - Web Audio API による効果音（SE）はヘッダーからワンタップで消音（ミュート）切り替え・設定永続化ができること。

## 4. アクセシビリティ要件 (Accessibility)

- **ズーム・視認性**:
  - ビューポート設定で 200% 以上の拡大ズームを許可する（`user-scalable=no` 等を禁止）。
  - 正解・不正解や警告・選択状態を色のみで表現せず、アイコン（⭕ / ❌ 等）とテキストを併用する。
- **セマンティクス & キーボード操作**:
  - ボタン・リンク・見出しには標準 HTML 要素（`<button>`, `<a>`, `<header>`, `<footer>` 等）を使用し、アイコンのみのボタンにはアクセシブルネーム（`aria-label` 等）を付与する。
  - モーダルダイアログ（ヘルプガイド、アカウント連携、法務・お問い合わせ）では `Escape` キーでの閉じる操作や適切な ARIA 属性を備える。
- **モーション配慮**:
  - `prefers-reduced-motion` が有効な環境ではアニメーション演出を抑制・無効化する。

## 5. セキュリティ & データ整合性要件 (Security & Data Integrity)

- **入力サニタイズ & XSS 対策**:
  - ユーザー入力（愛馬名カスタム編集など）は NFKC 正規化・制御文字除去・言語別ホワイトリスト検証および文字数制限を実施し、LocalStorage 復元時にもサニタイズを行う。
  - `dangerouslySetInnerHTML` の無検証利用を禁止し、外部リンクには `rel="noopener noreferrer"` を付与する。
- **認証 & 権限管理**:
  - パスワードを自前保持しないパスワードレス運用（Firebase 匿名認証 / Google・X OAuth SSO）とする。
  - 管理者権限はソースコードやセキュリティルールへ UID・メールアドレスをハードコードせず、Custom Claims または Firestore `admins/{uid}` コレクションで管理する。
- **データ改ざん防止 & プライバシー**:
  - Firestore セキュリティルール（`firestore.rules`）により本人・管理者以外の読み書きを遮断し、にんじん所持数上限（`<= 3`）や調教日数範囲（`0〜7`）等の整合性をサーバー側で検証する。
  - Firebase App Check（reCAPTCHA Enterprise / v3）およびクライアント側サニタイズ＋クラウド正本リコンサイルにより、不正リクエストやローカル改ざんを抑止する。
  - 秘密情報・APIキー等の機密情報はソースコードやログに直書きせず、環境変数および GitHub Secrets で管理する。
- **データ品質（一次ソース原則）**:
  - フレーズマスターデータは実在する海外競馬公式中継・インタビュー・公式辞典（JRA海外競馬英和辞典等）に準拠し、架空の表現や推測データを含めない。

## 6. 運用・スケーラビリティ・品質検証要件 (Operations & Quality)

- **サーバーレス・低コスト運用**:
  - Firebase Hosting / Authentication / Cloud Firestore / BigQuery のマネージド構成により、MAU 5,000人規模まで Google Cloud 無料枠〜極小コストでの運用を目標とする。
  - Firestore への書き込みは1問ごとに行わず、「調教完了時」「レース完了時」「主要状態変更時」に集約して書き込み回数を最適化する。
  - 退会時は物理削除を行わず論理削除（`isDeleted: true`）とし、誤操作時の管理者による復旧と累計統計の保全を両立する。
- **自動検証 & CI/CD**:
  - 変更時は `npm run lint`（oxlint）、`npm test`（Node.js テストランナー）、`npm run build`（TypeScript 型検査＋Vite ビルド）をすべてパスすることを完了基準とする。
  - `master` マージ時に GitHub Actions（`.github/workflows/firebase-deploy.yml`）による自動デプロイを行う。
