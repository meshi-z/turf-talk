Executive Summary & Product Vision

エグゼクティブサマリー & ビジョン

🏇 プロダクトタグライン
一般的な英語学習アプリでは絶対に教えてくれない、海外競馬の勝利騎手・調教師の「生のつぶやき・興奮」を直感で掴むマイクロラーニング
背景・コアプロブレム（現状の課題） PROBLEM
  • 海外G1の勝利騎手インタビューや現地公式中継は、日常英会話ができる人でも競馬特有のスラング・比喩表現（in the tank, on the bridle, dug deep 等）や早口の定型句によって聞き取れない。
  • 一般的な英語学習サービスには競馬の文脈が一切なく、一方で競馬英語の専門書はお勉強感が強すぎて日々の習慣として継続しづらい。
解決アプローチ（TurfTalk の提供価値） SOLUTION
  • 「毎日の調教（1日3問の直感4択）× 週末のレース出走（全5問）」という競馬ファンの生活リズムに合わせたゲーミフィケーションサイクルを提供。
  • 文法解説を排除し、「競馬ファンならパドックやレース映像で直感的に腑に落ちる1〜2行のワンポイント解説」と4週間の愛馬育成キャリアサイクルを組み合わせ、スキマ時間（1〜2分）で楽しく継続できる体験を実現。
項目 仕様・定義内容
プロダクト名 TurfTalk（ターフトーク｜海外競馬英語マイクロラーニング）
本番公開URL https://turftalk-jp.web.app/（Firebase Hosting / グローバルCDN配信）
現行バージョン v1.1.4（Phase 1 MVP 〜 Phase 4 クラウド・管理者基盤まで全マイルストーン実装完了）
一次ソース準拠原則 海外競馬公式中継、主要G1勝利騎手・調教師インタビュー、海外競馬メディア（Racing Post, Sporting Life, BloodHorse等）、およびJRA「海外競馬英和辞典」で実際に使われる表現のみを収録（AIによる架空造語や推測補完は厳禁）。

Target Personas & User Stories

ターゲットペルソナ & ユーザーストーリー

2.1 ターゲットペルソナ定義

Primary Persona：競馬玄人・英語中級 CORE TARGET
  • 人物像: 30〜40代男性、IT・オフィスワーク。競馬歴15年以上。海外主要G1（凱旋門賞、BC、ドバイ、香港等）も中継やYouTubeでリアルタイム観戦する層。
  • 英語力: 日常会話・基礎英語は理解できる（TOEIC等のスコアあり、平易な英文は読める）。しかし現地の早口インタビューや競馬特有の比喩・イディオムは聞き取れない。
  • 課題: 海外中継をリアタイで見ても、日本語の翻訳記事が出るまで騎手の生の声・手応えが正確にわからない。
  • 利用シーン: 平日の通勤・スキマ時間（1〜2分）、週末の開催前後のリラックスタイム。
Secondary Persona：ライト〜中級・英語初級 EXPANSION TARGET
  • 人物像: 20〜30代。ウマ娘や日本馬の海外挑戦ブームを機に競馬に本格参入（競馬歴2〜4年程度）。
  • 英語力: 高校基礎英語レベル。英語に苦手意識があり、文法解説や長文読解は挫折する。
  • 課題: 海外競馬の中継を見ても、現地の空気が全くわからない（騎手が喜んでいるのか、馬場や展開の言い訳をしているのかすら掴めない）。
  • 利用シーン: 移動中や就寝前、SNSを見る合間の「ながら利用」。

2.2 ユーザーストーリー一覧 (User Stories)

ID フェーズ 対象 ユーザーストーリー（As a ... / I want to ... / So that ...）
US-01 平日：調教 共通 ユーザーとして、平日に1日1〜2分（3問）の4択クイズを解きたい。なぜなら、負担なくスキマ時間で競馬英語の習慣を継続できるからだ。
US-02 平日：調教 Secondary 英語初級ファンとして、文法を気にせず「褒めているか／言い訳しているか」の空気感を直感で当てたい。なぜなら、雰囲気だけでも海外競馬の感情を掴みたいからだ。
US-03 平日：調教 共通 ユーザーとして、クイズ完了後に「調教済スタンプ」や「調子矢印」が記録される演出を見たい。なぜなら、愛馬を仕上げているような育成の達成感が得られるからだ。
US-04 週末：レース 共通 ユーザーとして、平日にインプットした知識を使って週末限定のレース（5問）に挑みたい。なぜなら、週末の競馬本番と連動したワクワク感を得られるからだ。
US-05 週末：レース Primary 競馬玄人として、実際の勝利騎手インタビューやレース展開を模した短文を解読したい。なぜなら、海外G1中継を字幕なしで楽しむための実力を試したいからだ。
US-06 アーカイブ 共通 ユーザーとして、一度解いたフレーズをカテゴリ別に一覧で振り返りたい。なぜなら、海外競馬の観戦中に手元で辞書代わりに確認したいからだ。
US-07 殿堂入り 共通 ユーザーとして、愛馬と4週間のデビューから海外G1ラストラン・引退までを駆け抜け、殿堂入りカードとして記録を残したい。なぜなら、1頭を仕上げて引退させる達成感と次世代へバトンを繋ぐロマンを楽しめるからだ。

Core Features & Gamification Mechanics

コア機能要件 & ゲームサイクル仕様

3.1 4択クイズエンジン & 2コース選択型調教（全120問マスター＋動的配信）

実戦フレーズを学ぶ「🌿 坂路調教（60問）」と、JRA海外競馬英和辞典準拠の基礎単語・用語を学ぶ「🪵 ウッドチップ調教（60問）」の2コース・計120問の静的マスターに加え、Cloud Firestore からの動的配信フレーズを統合して出題します。

コース区分 カテゴリ名 キー 収録数 代表的な収録フレーズ・用語例

type: phrase

競走馬の挙動・状態 reaction 15問 Turn of foot（瞬発力・キレ味）、Greenness（若さ）、Tenacity（勝負根性）、Sweating up（パドック発汗）、Refusal（飛越拒否）
着差・裁決・斤量 comment 15問 Short Head（短頭差）、Dead-heat（同着）、Stewards' Inquiry（審議）、Objection（異議申立）、Weight-for-Age（定量戦）
決定論的デイリー選出 PRNG

論理日付（YYYY-MM-DD）から32bitハッシュを生成し、Mulberry32 PRNGで未履修優先の3問を選出。同日中はリロードしても同じ3問が出題され、4択の並び順は毎回動的シャッフル。

1コース完了でデイリー達成 DAILY RULE

坂路またはウッドチップのいずれか1コースを完了した時点で当日達成（ストリーク+1、週間調教日数+1、レース解放）。同日に両コース受講しても日数は重複加算されず、正答問題のみ習得記録。

復習 & 追加トレーニング EXTRA

当日調教完了後も「本日の3問復習」および「追加トレーニング（未習得2問＋既習1問をランダム選出）」を何度でも受講可能。ゲームバランス保護のためストリークや調教日数は不変。

3.2 7日制調教・午前4時リセット・週末レース & にんじん救済システム

LOGIC 01 / 28:00 RESET
午前4時（28時）論理日付更新
深夜0:00〜3:59の学習も前日分として継続できるよう実時刻から4時間減算した論理日付（getLogicalDate）を採用。週の境界は月曜午前4時。
LOGIC 02 / 7-DAY TRAINING
7日制調教 & 余力ヒント付与
平日・土日問わず週最大7日まで調教日数をカウント。消化日数に応じ愛馬の調子と週末レースの「愛馬の余力（誤答1肢除外ヒント）」を付与（0〜2日: 0回 / 3〜4日: 1回 / 5〜7日: 2回）。
LOGIC 03 / HYBRID RACE
週末レース（土日限定・週1回）
初回調教完了で解放。「第1〜2問: 基礎単語 ➡ 第3〜5問: 実戦フレーズ」のハイブリッド5問構成。出走距離連動の残り距離バッジと実況テキストで臨場感を演出。
LOGIC 04 / CARROT RESCUE
にんじん温存還元 & ストリーク救済
レースで「愛馬の余力」を温存して完走すると未使用分の「にんじん 🥕」を獲得（最大3個所持）。未受講日が発生した際に1日1個自動消費し連続学習記録を救済。

3.3 競走馬4週間キャリアサイクル（全8毛色・馬名バリデーション・全8大路線）

1頭の愛馬を永遠に担当するのではなく、「4週間（Week 1 初陣 ➡ Week 2 前哨戦 ➡ Week 3 国内頂点 ➡ Week 4 世界挑戦・引退戦）」で1頭のキャリアを完走させるマイルストーン設計により、学習継続率とコレクション性を高めます。

① 馬名自動生成・手動編集とJRA/IFHA準拠セキュリティバリデーション

  • 自動生成（🎲 命名・毛色同時抽選）: 品格ある前半ワード20語×後半ワード20語から2〜9文字のカタカナ馬名を自動生成すると同時に、JRA基準8毛色を重み付き抽選。
  • 初回調教完了ロック: 馬名編集・再抽選・路線変更は初回調教完了前（hasTrained === false）まで可能。1回でも調教を完了すると引退まで確定ロック。
  • 言語別ハイブリッド検証 & XSS対策: 日本語馬名は2〜9文字（JRA基準）、英字馬名は2〜18文字（IFHA基準）。1文字入力および日本語と英字の混在は禁止。NFKC正規化・制御文字除去・ホワイトリスト検証によりHTMLタグ等の不正入力を完全拒否。

3.4 引退式セレモニー・二つ名（称号）授与・殿堂入りギャラリー & 世代継承

二つ名（称号）の自動授与ルール EPITHET
  1. 4戦全勝（4勝）: 不敗の世界覇者
  2. Week 3 + Week 4 連覇: 路線別最高称号（世界を翔ける至高の王者 / 華麗なる世界の女帝 / 電光石火の世界快速王 / 威風堂々たる中距離の皇帝 / 無尽蔵のワールドステイヤー / 砂塵を切り裂く剛脚王 / 砂塵を統べる世界覇王 / 伝説のグランドジャンパー）
  3. Week 4 制覇: 世界の頂に立つ名馬
  4. Week 3 制覇: 路線別国内王者称号（栄光のクラシック覇者 等全8種）
  5. 1勝以上: ターフを沸かせた実力馬
  6. 未勝利・累計12点以上: 堅実無比の名バイプレイヤー
  7. その他完走: ひたむきな挑戦者
世代交代時のデータ引き継ぎ・初期化ルール INHERITANCE
  • 次世代へ引き継ぐデータ: 連続学習ストリーク（streakDays）、にんじん所持数（carrotCount）、通算習得フレーズ（learnedPhraseIds / lapCount）、殿堂入り履歴（hallOfFame）、各フレーズの初習得パートナー馬記録（phrasePartners）。
  • 新世代で初期化されるデータ: careerHorse（generation + 1, currentWeek: 1, weight: 484, hasTrained: false）、週間調教消化日数（weekdayTrainingDays: 0, condition: 'heavy', horseWeight: 500）。
  • 同週末の連続出走防止ガード: 土日にWeek 4を完走して世代交代した場合、誕生した新馬は当該週末中は「🌿 新馬入厩・来週末デビュー」となり、翌週月曜午前4時の週替わり後にWeek 1出走が解放される。

System & Cloud Backend Architecture

システム・クラウドアーキテクチャ仕様

5.1 技術スタック & 全体アーキテクチャ構成図

サーバー常時稼働コストをゼロに抑えつつ、オフライン完全動作・高速表示・複数端末リアルタイム同期・管理者向け高度分析を両立するため、Google Cloud / Firebase のマネージドサーバーレスアーキテクチャを採用しています。

1. Client (SPA / PWA)Vite + React 19
TurfTalk Web App React 19, TypeScript, Tailwind CSS v4, Lucide Icons, Canvas透過合成エンジン
Workbox Service Worker vite-plugin-pwa による全静的アセット・馬イラスト・背景のオフラインキャッシュ
Browser APIs & Local Cache LocalStorage即時永続化、Web Speech API (TTS)、Web Audio API (効果音SE)
2. Delivery & SecurityFirebase Edge
Firebase Hosting グローバルCDN配信・SSL終端（turftalk-jp.web.app）
Firebase App Check reCAPTCHA Enterprise / v3 による不正クライアントアクセス遮断
GitHub Actions CI/CD master マージ時の自動Lint・テスト・ビルド・Hostingデプロイ
3. Auth & DatabaseFirebase Core
Firebase Authentication 初回自動匿名認証（CSPRNG 28文字UID）＋ Google / X (Twitter) OAuth SSO
Cloud Firestore users/{uid}（進捗・愛馬）、phrases/{id}（動的配信）、admins/{uid}
Firestore Security Rules 本人/管理者権限制御＋サーバー側整合性検証（にんじん上限<=3等）
4. Admin & AnalyticsBI Pipeline
Firebase Analytics training_completed, race_completed, horse_retired 等のイベント計測

Looker Studio & App Admin 消化率・枯渇予測BIダッシュボード＋アプリ内3タブ管理画面

5.2 2段階ユーザー認証モデル（匿名ゲスト利用 ➡ SSO昇格・連携解除）

① 初回匿名認証（登録不要） GUEST

初回アクセス時に会員登録画面を出さず、LocalStorageとFirebase匿名認証を自動開始。パスワードレス運用のためパスワード漏洩リスクは原理的にゼロ。

② アカウント昇格（データ保持） LINK SSO

任意タイミングで Google または X と linkWithPopup で連携。既存の調教履歴・愛馬・殿堂入りを100%維持したまま昇格。既存連携済アカウント検出時は signInWithCredential でポップアップブロックを回避。

③ 連携解除 & 論理削除退会 UNLINK / SOFT DELETE

unlink によるプロバイダ切り替え（reload + getIdToken(true) で即時リフレッシュ）に対応。退会時は物理削除せず isDeleted: true の論理削除とし、誤操作時の管理者復元と統計保全を両立。

5.3 Cloud Firestore データベース設計 & マルチデバイス同期

コレクションパス アクセス権限（firestore.rules） 主な格納データ・用途
users/{uid} 本人（request.auth.uid == uid）または管理者のみ読み書き可（carrotCount <= 3, learnedCount <= 1000 等の検証付） 基本認証属性、退会フラグ（isDeleted）、管理者集計用トップレベルサマリー項目（learnedCount, progressPercent, streakDays, currentHorseName, totalRaceWins 等）、および完全復元ペイロード progressData。
phrases/{phraseId} 全員読み取り可（allow read: if true）
管理者のみ書き込み可（allow write: if isAdmin()）		 動的配信用の新設・改訂フレーズマスター（situation, phrase, type, options[4], explanation, category, isPublished）。
admins/{adminId} 本人のみ読み取り可、クライアントからの書き込み全面禁止（Firebase Consoleからのみ登録） 管理者権限マスター。ソースコードやルールへのUID・メールアドレスのハードコードを排除。
  • リアルタイム複数端末同期（Issue #137）: ログイン連携済み端末間では Firestore の onSnapshot リアルタイム購読と、タブ・アプリ復帰時（visibilitychange / focus）の再購読・最新データ再取得を併用。初回クラウド同期完了前の古いローカルデータによる上書きを防止する保存ガード（shouldSkipCloudSave）を備えます。

5.4 動的フレーズ配信（3層ハイブリッドマージ）& 管理者分析基盤

  • 3層ハイブリッドフレーズ配信: 「第1層: バンドル内包静的マスター（120問・初回描画待ちゼロ）➡ 第2層: LocalStorageキャッシュ（turftalk_cached_cloud_phrases_v1）➡ 第3層: Firestore phrases 非同期フェッチ」の多層構成により、アプリ再ビルドなしで新問追加や解説改訂を即時配信。
  • コンテンツ枯渇予測 & BI分析: 未消化問題数が10問以下の「コンテンツ枯渇ユーザー」がアクティブ全体の15%を超えた際にアラートを表示し、新問題パック投入の意思決定を支援。
