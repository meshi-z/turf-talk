# Performance implementation rules

性能目標と計測条件の詳細は策定された場合 `docs/non-functional-requirements.md` を正本とする。

## Measurement

- 性能改善は推測ではなく計測結果（Lighthouse、Web Vitals等）に基づいて行う。
- 変更前後を同じデータ、環境、条件で計測する。
- 性能目標を満たさない場合は、計測値、条件、ボトルネック、残存リスクを報告する。

## Client performance (Mobile & Microlearning)

- モバイルデバイスでの快適な操作性を最優先とする（クイズのタップ反応速度、画面遷移のスムーズさ）。
- Shadcn UIコンポーネントを追加するときは、同時に追加される依存関係とバンドルサイズを確認する。
- 利用しないコンポーネントや依存関係を追加しない。
- アニメーションや演出ライブラリの追加時は、初期表示およびタップ時のレイテンシへの影響を事前に確認する。
- 不要な再レンダリングを避けるが、計測なしに過剰なメモ化を行わない。
- 画面外または初期表示に不要な機能は、必要に応じて遅延読み込み（Dynamic Import等）する。
- レイアウトシフト（CLS）を発生させないよう、クイズ選択肢や演出アイコンの表示領域を確保する。

## Data access & LocalStorage

- LocalStorageへの頻繁すぎる同期書き込みを避け、適切なタイミングで永続化する。
- 将来的にフレーズデータが増加した場合でも、初期表示に不要なデータは分割またはオンデマンド取得を検討する。

## User experience

- タップ直後の即時フィードバック（正解・不正解のハイライト等）を提供し、ユーザーを待たせない。
- アニメーションによって操作可能になるまでの時間を遅らせない。
