# Shadcn UI design system rules

## General policy

- UIコンポーネントの基盤としてShadcn UIを採用する。
- Shadcn UIは、完成済みライブラリを外部依存として利用するだけではなく、ソースコードをプロジェクトへ取り込んで保守する仕組みとして扱う。
- プロジェクトに追加されたShadcn UIコンポーネントは、このプロジェクトが所有・保守するコードとして扱う。
- CLI構成は`components.json`を正本とする。

## Component selection

- 新しいUIを実装する前に、既存の共通コンポーネントを確認する。
- 既存コンポーネントで実現できる場合は、新しいコンポーネントを作らない。
- 必要なコンポーネントがない場合は、Shadcn UI公式Registryを優先する。
- コミュニティまたは第三者Registryは、承認されたものだけを使用する。
- ページ固有コードにShadcn UIコンポーネントを複製しない。
- 複数箇所で使う組み合わせは、プロジェクト固有の共通コンポーネントにする。

## CLI and generated code

- Shadcn CLIのバージョンは、プロジェクトで承認されたバージョンを使用する。
- 承認なしに`latest`へ更新しない。
- コンポーネント追加前に、既存ファイルが上書きされないか確認する。
- 強制上書きオプションを無断で使用しない。
- CLI実行後は次を確認する。
  - 追加・変更されたソースコード
  - 追加された依存関係
  - `components.json`の変更
  - グローバルCSSの変更
  - ロックファイルの変更
- 生成されたコードを未確認のままコミットしない。

## Theming

- 色、背景、文字色、境界線、フォーカスリング、角丸にはセマンティックトークンを使用する。
- `background`、`foreground`、`primary`、`muted`、`destructive`、`border`、`input`、`ring`など、既存トークンを優先する。
- コンポーネント内にブランドカラーや状態色を直接記述しない。
- 新しい色を追加する場合は、用途を表すセマンティックな名前を付ける。
- 新しい背景色には、必要に応じて対応するforegroundトークンを定義する。
- ライトテーマとダークテーマの両方を定義する。
- テーマ変更時は、文字、アイコン、境界線、状態表示のコントラストを確認する。
- `ring`やフォーカス表示を削除しない。
- `components.json`でCSS変数が有効な場合は、インラインの色指定ではなくCSS変数を使用する。

## Accessibility

- Shadcn UIの初期実装がアクセシブルであることを、プロジェクト全体のアクセシビリティ保証とは見なさない。
- コンポーネントを変更するときは、元のセマンティクス、ARIA属性、キーボード操作、フォーカス管理を維持する。
- 標準HTML要素で表現できる場合は、標準要素を優先する。
- `div`や`span`をボタン、リンク、チェックボックスの代用にしない。
- アイコンだけのボタンにはアクセシブルネームを設定する。
- エラー、警告、選択状態を色だけで表現しない。
- フォーム入力には可視ラベルまたは同等のアクセシブルネームを設定する。
- Dialog、Popover、Dropdown Menuなどでは、フォーカス移動、Escape操作、フォーカス復帰を確認する。
- Tooltipだけに必須情報を置かない。
- `prefers-reduced-motion`を考慮する。

## Composition

- Shadcn UIコンポーネントの合成を優先し、大規模で用途が曖昧な万能コンポーネントを作らない。
- ビジネスロジックを`components/ui/`に入れない。
- `components/ui/`には汎用UIプリミティブを置く。
- ドメイン固有コンポーネントは、機能またはドメインのディレクトリに置く。
- Variantは既存の仕組みに合わせ、一貫したAPIを維持する。
- `className`の上書きによって重要な状態スタイルやアクセシビリティ表示を消さない。

## Responsive behavior

- モバイルを含む対象画面幅（スマートフォン優先）で快適に操作可能にする。
- 固定幅によってテキストや操作要素が切れないようにする。
- 長い日本語、英数字、エラーメッセージ、フレーズ英文を考慮する。
- ローディング、空状態、エラー、無効、完了状態のフィードバックを考慮する。
